# Venturine v0.3.1

A maintenance release for the v0.3.0 beta. It fixes two problems found in native testing and improves the README. There are no new skills, agents or calculator operations: the plugin still has 12 skills and 6 agents, and the calculator engine stays at 0.2.1.

## Fixed

- **Calculator permission guidance.** `unit-economics`, `scenario-comparison`, `pricing-analysis` and `go-to-market` now tell you before the first calculator command that Claude Code will ask for permission, show the exact command, and run commands one at a time. They ask you to allow only the exact calculator script path, never `python3` or `Bash` in general. If you decline, they do not compute the figures another way and present them as engine output: those figures are labeled "manual calculation, not engine-validated". Agents still have no shell access, and no skill sets `allowed-tools`.
- **Multi-step requests stopping after intake.** When a request named several steps, `venture-intake` could end the turn after its own output. It now continues to the next requested step, and asks only when a missing fact makes that step impossible.

## Documentation

- The README now says who Venturine is for, how to allow the calculator (with the exact allow-rule form), how to run a complete analysis step by step, and where to report bugs and request features.
- The security document explains why calculator permission is yours and scoped to one script.

## Compatibility

No change to the handoff format, calculator operations or default behavior. Handoffs and results from v0.3.0 stay valid.

## Upgrade

Update the plugin through Claude Code's plugin manager. No configuration is needed. To install it fresh, run `/plugin marketplace add maddyzohadi/venturine` and then `/plugin install venturine@venturine-marketplace`.

## Known limitations

- Skill and agent behavior depends on an AI model following written instructions. Venturine does not guarantee that every skill or agent is invoked automatically. In a long multi-step run the model may do a step itself instead of invoking its skill (for example writing the report directly instead of using `business-report`). Name the skills you want, and check which ones ran.
- Tests cover the deterministic parts (calculators, validator, structure) and wording, and a small number of native runs checked the rest, so wrong or missing findings are still possible.
- Repeat-purchase customer lifetime value is not built, and the price comparison does not model how demand responds to price.
- The five-minute quick start has not been timed with outside testers.
